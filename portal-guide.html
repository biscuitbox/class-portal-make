AI와 함께 만드는 우리 반 안내판

교실 TV에 띄워 두는 학급 안내판을 AI에게 말로 부탁해서 만들고, 인터넷 주소로 올리고, 여러 기기에서 함께 보도록 연결하는 과정입니다. 프로그래밍을 몰라도 이 페이지를 위에서부터 차례로 따라 하면 됩니다.

전체 흐름

1. AI로 만들기프롬프트를 붙여넣고 미리보기 확인 · 약 20분 2. 내 파일로 저장index.html 파일로 받아 두기 · 약 10분 3. 고치고 더하기탭·타이머·뽑기·급식 등 · 원하는 만큼 4. 인터넷에 올리기깃허브 페이지로 내 주소 만들기 · 약 30분 5. 여러 기기 공유파이어베이스 연결 · 약 40분 (선택)

1~4단계까지만 해도 교실 TV에서 쓸 수 있는 안내판이 완성됩니다. 5단계는 선생님 컴퓨터에서 고친 내용이 교실 TV와 학생 기기에 바로 보이게 하고 싶을 때 이어서 하세요. 한 번에 다 하지 않아도 됩니다. 단계가 끝날 때마다 인쇄용 유인물에 체크해 두면 다음에 이어 하기 편합니다.

HTML 파일

웹페이지 한 장이 들어 있는 파일입니다. 더블클릭하면 크롬에서 열립니다. 우리 안내판은 index.html 파일 하나입니다.

📋 프롬프트 1 — 기본 안내판
교실 TV(가로 화면)에 띄워 둘 "우리 반 안내판" 웹페이지를 만들어 줘.

[목표와 환경]
- HTML·CSS·자바스크립트를 모두 HTML 파일 하나에 넣어 줘. 외부 라이브러리와 외부 글꼴은 쓰지 마.
- 크롬에서 파일을 더블클릭해서 열어도 바로 돌아가야 해.
- 글꼴은 "Malgun Gothic", "Apple SD Gothic Neo", sans-serif 를 써.

[디자인과 배치]
- 맨 위 머리말: 왼쪽에 학급 이름(예: 2학년 3반)과 급훈, 오른쪽에 오늘 날짜·요일·현재 시각(1분마다 바뀜).
- 그 아래 카드 3개를 가로로 나란히:
  ① 오늘의 시간표 — 1교시~7교시 과목
  ② 알림장 — 할 일 목록. 체크하면 줄이 그어짐
  ③ 다가오는 일정 — 일정 이름과 날짜, D-3·D-DAY 표시, 가까운 날짜 순서
- 교실 뒤에서도 보이게 글씨를 크게. 모니터(가로 1000px 이상)에서는 페이지 스크롤 없이 화면에 꼭 맞게 하고,
  내용이 많으면 그 카드 안에서만 스크롤되게.
- 휴대폰처럼 좁은 화면에서는 카드가 세로로 쌓이게.

[동작 규칙]
- 평소에는 보기 전용. "✏️ 편집 모드" 단추를 눌렀을 때만 학급 이름·급훈·시간표를 고치고
  알림과 일정을 추가·삭제할 수 있게.
- "전체 지우기" 단추는 편집 모드에서만 보이고, 누르면 페이지 안에 확인 상자를 띄워 한 번 더 물어보게.
  학급 이름과 급훈은 남기고 시간표·알림·일정만 지워.
- alert()와 confirm()은 쓰지 말고, 안내는 화면 위쪽에 잠깐 나타나는 글상자로 보여 줘.

[데이터 보관]
- 처음 열었을 때 시간표·알림·일정은 비어 있게 해 줘(예시 내용을 미리 채우지 마).
- 입력한 내용은 localStorage에 저장해서 새로고침해도 남게.
- 화면 아래에 "개인정보 보호를 위해 학생 이름 대신 번호를 쓰세요" 안내 문구를 넣어 줘.

이 프롬프트는 네 덩어리로 되어 있습니다 — 목표와 환경 · 디자인과 배치 · 동작 규칙 · 데이터 보관. 나중에 내 프롬프트를 쓸 때도 이 네 가지를 말해 주면 AI가 훨씬 정확하게 만듭니다.

3 미리보기에서 눌러 보기

  • 제미나이: 오른쪽 캔버스 위쪽의 미리보기가 눌려 있는지 확인합니다. (코드를 누르면 코드가 보입니다)
  • Claude: 오른쪽 창에 화면이 뜹니다. 안 보이면 답 안의 상자를 누릅니다.
  • ChatGPT: 코드 상자 위쪽의 미리보기(Preview)를 누릅니다.

✏️ 편집 모드를 눌러 알림을 하나 추가해 보세요. 체크하면 줄이 그어지면 성공입니다.

미리보기 창은 좁습니다. 그래서 카드가 세로로 쌓여 보일 수 있습니다. 정상입니다. 2단계에서 파일로 저장해 크롬 전체 화면으로 열면 가로로 나란히 보입니다.
1단계 끝 — AI 화면에 안내판이 보이고, 편집 모드에서 알림을 추가할 수 있다.

2단계 내 컴퓨터에 파일로 저장하기 약 10분

AI 화면은 임시 공간입니다. 인터넷에 올리려면 내 컴퓨터의 파일이 있어야 합니다. 파일 이름은 반드시 index.html로 합니다. 이 이름이어야 4단계에서 주소 끝에 파일 이름을 붙이지 않아도 열립니다.

A 내려받기 단추가 있을 때 (제미나이)

  1. 캔버스 오른쪽 위 내보내기 › 코드 다운로드 를 누릅니다.
  2. 크롬 오른쪽 위의 다운로드 표시(↓)를 눌러 폴더에 표시를 누르면 받은 파일이 보입니다. 보통 내 PC › 다운로드 폴더입니다.
  3. 파일을 바탕화면의 우리반안내판 폴더로 끌어다 옮깁니다.
  4. 파일을 한 번 클릭하고 F2 를 눌러 이름을 index.html로 바꿉니다. "확장명을 변경하면…" 경고가 나오면 예.

B 내려받기 단추가 없거나 잘 안 될 때 — 복사해서 메모장으로 저장 (모든 AI 도구 공통)

  1. AI 화면에서 코드를 보이게 하고(제미나이는 코드 단추) 코드 상자의 복사 단추를 누릅니다. 복사 단추가 없으면 코드 안을 한 번 클릭하고 Ctrl + A, Ctrl + C.
  2. 윈도우 시작 단추 → 메모장 을 검색해 엽니다 → Ctrl + V 로 붙여넣습니다.
  3. 파일 › 다른 이름으로 저장 을 누릅니다.
  4. 저장 창에서 왼쪽 바탕 화면 → 우리반안내판 폴더를 엽니다.
  5. 파일 형식을 모든 파일 (*.*) 로 바꿉니다. ← 가장 많이 빠뜨립니다
  6. 인코딩이 UTF-8 인지 확인합니다.
  7. 파일 이름에 index.html 을 적고 저장.
코드 처음과 끝을 확인하세요. 복사한 코드는 <!DOCTYPE html>로 시작해서 </html>로 끝나야 합니다. 앞뒤에 AI의 설명 글이 섞여 들어가면 화면에 이상한 글자가 보입니다.

C 더블클릭으로 열어 보기

index.html을 더블클릭하면 크롬이 열리면서 안내판이 보입니다. 크롬이 아닌 다른 프로그램이 열리면 파일에서 마우스 오른쪽 단추 → 연결 프로그램 › Google Chrome.

이제 ✏️ 편집 모드에서 우리 반 이름·급훈·시간표를 넣어 보세요. 새로고침(F5)해도 남아 있으면 성공입니다.

고칠 때마다 번호를 붙여 보관해 두면 안전합니다. 잘 되는 버전이 생기면 index_1.html, index_2.html처럼 복사본을 남겨 두세요. 망가지면 언제든 돌아갈 수 있습니다. 인터넷에 올리는 파일은 항상 index.html 하나입니다.
2단계 끝 — 바탕화면 폴더의 index.html을 더블클릭하면 안내판이 열린다.

3단계 고치고 기능 더하기 원하는 만큼

바이브코딩의 핵심은 보고 → 말하고 → 다시 보는 반복입니다. 전체를 다시 만들어 달라고 할 필요 없이, 고칠 부분만 짧게 말하면 됩니다.

이렇게 말하면 됩니다

"학급 이름 글씨를 더 크게 해 줘. 나머지는 그대로."
"알림장 카드 배경을 연한 노란색으로 바꿔 줘."
"편집 모드 단추를 눌러도 아무 일이 없어. 왜 그런지 찾아서 고쳐 줘."
"화면이 하얗게만 나와. 오류를 찾아서 고쳐 줘."
"방금 바꾼 것을 되돌려 줘."
세 가지 습관
  • 한 번에 하나씩. 여러 가지를 한꺼번에 부탁하면 어디서 망가졌는지 찾기 어렵습니다.
  • 같은 대화창에서 이어서. AI는 그 대화 안에서 만든 것만 기억합니다. 대화 제목을 우리반 안내판으로 바꿔 두면 다시 찾기 쉽습니다.
  • 고친 뒤에는 2단계처럼 다시 저장. AI 화면에서만 바뀌고 내 index.html은 그대로입니다.

새 대화에서 이어 가야 할 때

대화를 잃어버렸거나 다른 AI 도구로 옮길 때는, 내 index.html을 AI에게 먼저 보여 줘야 합니다.

  1. 입력창의 ＋ (또는 📎) → 파일 업로드 → index.html을 고릅니다. 파일이 올라가지 않으면 메모장으로 index.html을 열어 Ctrl+A, Ctrl+C 한 뒤 입력창에 붙여넣습니다.
  2. 그 아래에 이렇게 적고, 이어서 바꿀 내용을 씁니다.

바꿀 내용:
"// 기존 코드 그대로" 같은 줄이 보이면 그대로 저장하지 마세요. AI가 길이를 줄이려고 코드를 생략한 것입니다. 그대로 저장하면 기능이 사라집니다. "생략하지 말고 전체 파일로 다시 줘"라고 하세요. 파일이 길어질수록 자주 생기므로, 제미나이 캔버스나 Claude처럼 화면 옆 창에서 고치는 도구가 더 편합니다.

① 탭 만들기 + 주간 시간표

📋 프롬프트 — 탭과 시간표
지금 안내판은 그대로 두고, 머리말 아래에 탭 메뉴를 만들어 줘.
- 첫 탭은 "📋 안내판"(지금 화면), 두 번째 탭은 "🗓️ 시간표".
- 시간표 탭: 월~금 × 1~7교시 표. 오늘 요일 칸은 색으로 표시하고,
  지금 진행 중인 교시는 노란색으로 강조. 교시 시작 시각은 9:00부터 45분 수업, 10분 쉬는 시간,
  점심은 4교시 뒤 12:30~13:30.
- 표 위에 지금 몇 교시인지, 다음은 무슨 수업인지 크게 보여 줘.
- "✏️ 시간표 수정"을 눌렀을 때만 칸을 고칠 수 있고, localStorage에 저장.
- 안내판의 "오늘의 시간표" 칸이 비어 있으면 시간표 탭의 오늘 수업을 대신 보여 줘.
- 모니터에서는 탭 화면도 페이지 스크롤 없이 한 화면에 맞게.

우리 학교 시정에 맞게 시각을 바꿔서 보내세요. (예: "1교시 8:50 시작")

② 타이머

📋 프롬프트 — 타이머
탭 메뉴에 "⏱️ 타이머" 탭을 추가해 줘.
- 1분·3분·5분·10분 빠른 단추와 분·초 직접 입력.
- 시작·일시정지·초기화 단추. 남은 시간을 화면 가운데에 아주 크게.
- 마지막 10초는 빨간색, 끝나면 화면이 깜빡이고 짧은 소리(Web Audio)로 알려 줘.
- 다른 탭으로 갔다가 돌아와도 시간은 계속 흐르게.

③ 자리 뽑기 · 모둠 뽑기 · 발표 순서

📋 프롬프트 — 뽑기 도구
탭 메뉴에 "💺 자리 뽑기", "👥 모둠 뽑기", "🎤 발표 순서" 탭을 추가해 줘.
- 학생 이름은 쓰지 않고 번호(1번~전체 인원)만 써. 전체 인원과 결석 번호(쉼표로 구분)를
  세 탭이 함께 쓰고, localStorage에 저장.
- 자리 뽑기: 가로·세로 자리 수를 정하면 번호를 무작위로 배치. 교탁은 화면 위쪽.
  결과는 칠판에서도 보이게 크게.
- 모둠 뽑기: 모둠 수 또는 모둠당 인원을 고르면 무작위로 나눔.
- 발표 순서: 무작위 순서를 만들고, "다음" 단추로 한 명씩 크게 보여 주기.
- 모두 "다시 뽑기" 단추가 있고, 결과는 새로고침해도 남게.

④ 학생 화면 (보기 전용 주소)

📋 프롬프트 — 학생 화면
학생용 보기 화면을 만들어 줘.
- 주소 끝에 ?mode=student 를 붙여서 열면 처음부터 학생 화면으로 시작.
- 학생 화면에서는 편집 모드 단추, 전체 지우기, 모둠 뽑기·발표 순서 탭을 숨겨.
- 머리말 색을 초록색 계열로 바꾸고 "🎓 학생 공개 화면" 표시를 붙여서 교사 화면과 구별되게.
- 교사 화면 머리말에는 "🎓 학생 화면으로 보기" 단추를 두고,
  학생 화면에서는 "교사용으로 돌아가기" 단추를 보여 줘.

학생용 주소는 4단계가 끝나면 생깁니다: https://내아이디.github.io/class-portal/?mode=student

⑤ 오늘 급식 (나이스 자료)

교육부 나이스(NEIS) 교육정보 개방 포털의 급식 자료를 불러옵니다. 먼저 우리 학교 코드 두 개가 필요합니다.

  1. 아래 칸에 학교 이름을 정확히 적고 코드 찾기를 누릅니다. 새 탭에 글자가 가득한 화면이 뜹니다.
  2. Ctrl + F 로 ATPT_OFCDC_SC_CODE를 찾아 옆의 값(예: C10)을, SD_SCHUL_CODE를 찾아 옆의 값(예: 7181109, 숫자 7자리)을 아래 칸에 적습니다.
  3. 이름이 같은 학교가 여러 곳이면 ORG_RDNMA(주소)를 보고 우리 학교 것을 고릅니다.
🔎 코드 찾기 (새 탭)
📋 프롬프트 — 오늘 급식
탭 메뉴에 "🍚 오늘 급식" 탭을 추가해 줘.
- 나이스 교육정보 개방 포털 급식 API를 fetch로 불러와:
  https://open.neis.go.kr/hub/mealServiceDietInfo?Type=json
  &ATPT_OFCDC_SC_CODE=우리교육청코드&SD_SCHUL_CODE=우리학교코드
  &MLSV_FROM_YMD=이번주월요일&MLSV_TO_YMD=이번주금요일
- 인증키 없이 부르면 한 번에 5건까지만 오니까, 이번 주 월~금 점심만 불러와.
- 오늘 메뉴는 크게, 이번 주 메뉴는 아래에 작게. 메뉴 이름 뒤의 알레르기 번호(예: 1.5.6.)는
  메뉴 아래 작은 글씨로 따로 보여 줘. 메뉴의 <br/>은 줄바꿈으로.
- 지난주·이번 주·다음 주 단추.
- 불러오지 못하면(인터넷 끊김 등) 화면이 멈추지 말고 "급식 정보를 불러오지 못했어요" 안내.
- 같은 주 자료는 localStorage에 잠시 보관해서 탭을 열 때마다 다시 부르지 않게.
급식은 미리보기에서 안 나올 수 있습니다. AI 미리보기 창은 바깥 인터넷 접속을 막는 경우가 많습니다. 파일로 저장해 크롬에서 열거나, 4단계에서 올린 내 주소에서 확인하세요.

⑥ 칠판·종이 테마 바꾸기

📋 프롬프트 — 테마
디자인 테마를 두 가지로 만들고 머리말 단추로 바꿀 수 있게 해 줘.
- "칠판" 테마: 짙은 초록 칠판 배경, 분필 같은 흰 글씨와 노란 강조색, 나무 테두리 머리말.
  어두운 교실 TV에서 눈이 편하게.
- "종이" 테마: 크림색 공책 종이 배경, 진한 글씨. 밝은 교실의 프로젝터용.
- 고른 테마는 기기마다 localStorage에 기억하고, 주소 끝에 ?theme=paper 또는 ?theme=chalk 를
  붙이면 그 테마로 열리게.
- 색은 CSS 변수로 정리해서 두 테마 모두 글씨가 잘 읽히게(명도 대비 충분히).

⑦ 알림장 순서 끌어서 바꾸기

📋 프롬프트 — 알림 순서 바꾸기
편집 모드에서 알림장 항목의 순서를 끌어서 바꿀 수 있게 해 줘.
- 각 알림 왼쪽에 ⠿ 손잡이를 두고, 손잡이를 잡고 끌어서 놓으면 순서가 바뀌게.
- 마우스와 전자칠판 터치 모두 되도록 Pointer 이벤트로 만들고, 손잡이에 touch-action:none.
- 손잡이를 누른 상태에서 ↑↓ 키로도 한 칸씩 옮길 수 있게.
- 놓는 순간 localStorage에 저장. 보기 모드와 학생 화면에서는 손잡이를 숨겨.
내 아이디어로 직접 써 보세요. 위 프롬프트처럼 무엇을 · 어디에 · 누르면 어떻게 · 저장은 어떻게를 적으면 됩니다. 예: "탭 메뉴에 🗑️ 청소구역 탭을 추가해 줘. 구역 이름과 인원을 정하면 번호를 무작위로 배정하고, 결과는 저장해 줘."
3단계 끝 — 원하는 기능을 넣은 index.html을 바탕화면 폴더에 저장했다.

4단계 깃허브 페이지로 인터넷에 올리기 약 30분

여기까지는 내 컴퓨터에서만 열립니다. 깃허브에 올리면 교실 TV·전자칠판·휴대폰 어디서나 https://아이디.github.io/저장소이름/ 주소로 열 수 있습니다. 깃허브 화면은 영어로 나옵니다. 아래에서 이렇게 생긴 글자를 그대로 찾아 누르면 됩니다.

1 깃허브 가입하기 (처음 한 번)

  1. 주소창에 github.com → 오른쪽 위 Sign up.
  2. 화면 안내에 따라 Email(이메일), Password(비밀번호), Username(아이디), Your Country/Region(South Korea)을 넣고 Continue / Create account.
  3. 사람인지 확인하는 퍼즐을 풉니다.
  4. 메일함을 열어 GitHub에서 온 숫자 코드를 화면에 입력합니다.
  5. 질문 화면(팀 규모, 관심사 등)이 나오면 아무거나 고르거나 Skip. 요금제를 묻는다면 무료(Free)를 고릅니다.
아이디(Username)가 그대로 주소가 됩니다.
  • 영문 소문자·숫자·하이픈(-)으로 짧게. 예: haeyeon-teacher → haeyeon-teacher.github.io
  • 실명이나 학교 이름은 넣지 않는 편이 안전합니다. 정한 아이디는 유인물과 위의 내 정보 넣기에 적어 두세요.

2 저장소 만들기

  1. 로그인한 상태에서 오른쪽 위 ＋ ▾ → New repository.
  2. Repository name 칸에 class-portal (영문 소문자, 띄어쓰기 대신 하이픈).
  3. 공개 범위(visibility)는 Public. ← Private이면 무료 계정에서는 페이지가 열리지 않습니다.
  4. Add README를 On으로 켜거나 체크합니다. ← 꼭 켜세요 (아래 ⚠️ 참고)
  5. 맨 아래 초록색 Create repository.
Add README를 켜지 않고 만들었다면? 저장소가 텅 비어 있어서 3번에서 고를 Branch가 나오지 않습니다. 지우고 다시 만들 필요 없이, 바로 다음 단계에서 index.html을 올리면 해결됩니다.

3 index.html 올리기

  1. 방금 만든 저장소 첫 화면에서 초록 Code 단추 왼쪽의 Add file ▾ → Upload files. (저장소가 비어 있으면 가운데의 uploading an existing file 글자를 누릅니다)
  2. 바탕화면 폴더의 index.html을 화면 가운데로 끌어다 놓습니다. (또는 choose your files를 눌러 고르기)
  3. 아래쪽 초록 Commit changes.
  4. 저장소 첫 화면 파일 목록에 index.html이 보이면 성공입니다.
폴더째 끌어다 놓지 마세요. 폴더를 통째로 올리면 저장소 안에 폴더가 생기고 주소가 달라집니다. 폴더를 연 뒤 파일만 끌어다 놓으세요. index_1.html 같은 보관용 복사본은 올리지 않아도 됩니다.

4 깃허브 페이지 켜기 (처음 한 번)

  1. 저장소 위쪽 메뉴 줄 맨 오른쪽 ⚙ Settings. (창이 좁아 안 보이면 … 를 눌러 그 안에서)
  2. 왼쪽 메뉴를 아래로 내려 Code, planning, and automation 묶음의 Pages.
  3. Build and deployment 아래 Source가 Deploy from a branch 인지 확인합니다.
  4. Branch에서 None을 눌러 main으로 바꾸고, 옆 칸은 / (root) 그대로 → Save.
  5. 1~2분 기다린 뒤 이 화면을 새로고침(F5)하면 맨 위에 Your site is live at https://… 가 나타납니다. 그것이 내 주소입니다.

내 주소: https://내아이디.github.io/class-portal/

5 고친 파일 다시 올리기 (그다음부터 매번)

3단계에서 고친 index.html을 같은 이름 그대로 다시 Add file › Upload files › Commit changes 하면 덮어써집니다. 1~2분 뒤 내 주소에서 Ctrl + F5(강력 새로고침)로 확인하세요.

6 교실 TV에서 열어 두기

  • 교실 컴퓨터 크롬에서 내 주소를 열고 주소창 오른쪽 ☆ 를 눌러 북마크.
  • 켤 때마다 자동으로 열리게: 크롬 오른쪽 위 ⋮ → 설정 › 시작 그룹 › 특정 페이지 또는 페이지 모음 열기 › 새 페이지 추가 → 내 주소.
  • F11 을 누르면 주소창 없이 전체 화면이 됩니다. 다시 F11 하면 돌아옵니다.
  • 학생 휴대폰·태블릿용으로는 학생용 주소(주소 끝에 ?mode=student)를 알려 주세요.
올리고 나면 안내판 내용이 비어 있습니다 — 고장이 아닙니다. 내용은 localStorage(브라우저 수첩)에 들어 있는데, 이 수첩은 기기마다, 주소마다 따로 있습니다. 내 컴퓨터의 파일로 열었을 때 적은 내용은 인터넷 주소에서는 보이지 않습니다. 교실 TV에서 내 주소를 열고 ✏️ 편집 모드로 다시 적으세요. 한 곳에서 고친 내용을 모든 기기에서 보려면 5단계를 하세요.
4단계 끝 — 교실 TV에서 내 주소로 안내판이 열린다.

5단계 파이어베이스로 여러 기기에서 함께 보기 약 40분 · 선택

선생님이 교무실 컴퓨터나 휴대폰에서 고치면 교실 TV와 학생 화면에 바로 바뀌도록 연결합니다. 누구나 볼 수는 있지만, 고치는 것은 선생님 구글 계정으로 로그인했을 때만 되게 만듭니다. 파이어베이스 화면은 한국어로 나옵니다.

결제 정보는 등록하지 마세요. 무료 요금제(Spark)로 충분합니다. 결제 수단이 없으면 무료 사용량을 넘어도 돈이 나가지 않고 그날 기능만 잠시 멈춥니다. 중간에 요금제 업그레이드를 권하는 창이 나와도 닫으면 됩니다.

1 프로젝트 만들기

  1. 주소창에 console.firebase.google.com → 구글 계정으로 로그인.
  2. 새 Firebase 프로젝트 만들기 (또는 프로젝트 만들기)를 누릅니다.
  3. 프로젝트 이름을 영문으로: 예) class-portal → 약관 동의 체크 → 계속.
  4. Gemini·AI 도움 기능을 묻는 화면은 그대로 두거나 꺼도 됩니다 → 계속.
  5. Google 애널리틱스는 끄고(사용 설정 해제) → 프로젝트 만들기.
  6. 1분쯤 기다리면 "새 프로젝트가 준비되었습니다" → 계속.
학교 계정에서 프로젝트를 만들 수 없다는 오류가 나면 기관 정책 때문입니다. 개인 Gmail 계정으로 다시 로그인해서 하세요.

2 구글 로그인 켜기

  1. 왼쪽 메뉴 제품 카테고리에서 보안 › Authentication.
  2. 처음이면 시작하기.
  3. 위쪽 탭 중 로그인 방법 → 제공업체 목록에서 Google.
  4. 사용 설정 스위치를 켜고 → 프로젝트 지원 이메일에서 내 이메일을 고르고 → 저장.
  5. 목록에서 Google 옆이 사용 설정됨으로 바뀌면 끝.

메뉴를 못 찾겠으면 왼쪽 위 제품 검색에 Authentication을 입력해도 됩니다. Firestore도 같은 방법으로 찾을 수 있습니다.

3 데이터베이스(Firestore) 만들기

  1. 왼쪽 메뉴 데이터베이스 및 스토리지 › Firestore.
  2. 데이터베이스 만들기 (또는 데이터베이스 추가).
  3. 버전(Edition)을 물으면 Standard(표준) → 다음.
  4. 데이터베이스 ID는 비워 두거나 (default) 그대로. 위치는 asia-northeast3 (Seoul) → 다음.
    위치는 나중에 바꿀 수 없지만, 다른 곳을 골라도 동작에는 문제없습니다.
  5. 보안 규칙은 프로덕션 모드로 시작 → 만들기. (규칙은 바로 다음 4번에서 넣습니다)

4 보안 규칙 붙여넣고 게시하기 ← 가장 중요

"누구나 읽을 수 있고, 선생님 이메일로 로그인했을 때만 쓸 수 있다"는 규칙입니다. 아래 노란 글자가 내 이메일로 바뀌었는지 꼭 확인하세요. (내 정보 넣기에 적으면 저절로 바뀝니다)

  1. Firestore 화면 위쪽 탭에서 규칙.
  2. 편집 칸 안을 클릭 → Ctrl + A 로 원래 내용을 전부 고르고 → Delete.
  3. 아래 규칙 복사 → 편집 칸에 Ctrl + V.
  4. 위쪽 파란 줄의 게시. "게시되지 않은 변경사항"이 사라지면 끝.
🔒 보안 규칙
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // 우리 반 안내판 — 누구나 보고, 선생님 계정만 고친다
    match /classPortal/{docId} {
      allow read: if true;
      allow write: if request.auth != null
                   && request.auth.token.email == '선생님이메일@gmail.com'
                   && request.auth.token.email_verified == true;
    }

    // 그 밖의 모든 곳은 막는다
    match /{document=**} {
      allow read, write: if false;
    }
  }
}
이메일은 한 글자도 틀리면 안 됩니다. 대문자·소문자, 점(.) 하나까지 로그인할 계정과 똑같아야 합니다. 틀리면 로그인은 되는데 저장할 때 permission-denied(권한 없음)가 납니다.

5 웹 앱 등록하고 설정값(firebaseConfig) 복사하기

  1. 왼쪽 위 ⚙ 설정 › 일반 (프로젝트 설정 화면).
  2. 화면을 아래로 내려 내 앱 칸에서 </> 모양(웹) 아이콘을 누릅니다. (처음 만든 프로젝트라면 프로젝트 개요 화면 가운데의 </> 아이콘이나 + 앱 추가 › 웹도 같습니다)
  3. 앱 닉네임에 class-portal → 그 아래 Firebase 호스팅을 함께 설정하는 체크 상자는 비워 둠 → 앱 등록.
  4. SDK 추가 화면에서 <script> 태그 사용을 고르면 코드가 나옵니다. 그중 const firebaseConfig = { 부터 }; 까지만 마우스로 끌어 고르고 Ctrl+C.
  5. 복사한 것을 위의 내 정보 넣기 → firebaseConfig 칸에 붙여넣어 두세요. → 화면의 콘솔로 이동.
firebaseConfig는 공개되어도 괜찮은 값입니다. 웹페이지 안에 들어가서 누구나 볼 수 있게 되는 것이 정상이고, 데이터는 4번의 보안 규칙이 지킵니다. 다만 서비스 계정 키(비공개 키 파일, private_key가 들어 있는 것)는 절대로 AI에게 주거나 파일에 넣지 마세요. 이 과정에서는 필요 없습니다.

6 승인된 도메인에 내 주소 넣기 ← 빠뜨리기 쉬움

구글 로그인 창은 미리 허락한 주소에서만 열립니다. 깃허브 페이지 주소를 허락해 줍니다.

  1. 왼쪽 메뉴 보안 › Authentication → 위쪽 탭 설정.
  2. 가운데 목록 도메인 아래 승인된 도메인 → 오른쪽 도메인 추가.
  3. 아래 값을 그대로 넣고 추가.

넣을 값: 내아이디.github.io

https://와 뒤의 /class-portal/은 빼고 아이디.github.io만 넣습니다. 형식이 틀리면 로그인할 때 auth/unauthorized-domain 오류가 납니다.

7 AI에게 파이어베이스 연결 부탁하기

3단계와 같은 대화창(또는 새 대화에 index.html 첨부)에 붙여넣습니다. 노란 글자 두 곳(firebaseConfig, 이메일)이 내 값으로 바뀌었는지 확인하고 보내세요.

📋 프롬프트 — 파이어베이스로 여러 기기 공유
지금 만든 안내판에 파이어베이스를 연결해서, 선생님이 고친 내용이 교실 TV와 학생 화면 등
다른 기기에도 바로 보이게 해 줘. 지금 있는 기능과 디자인은 그대로 두고, 생략 없이 전체 파일로 줘.

[연결 방식]
- 파이어베이스 자바스크립트 SDK 12.19.0을 아래 주소에서 모듈로 불러와(type="module" 또는 동적 import):
  https://www.gstatic.com/firebasejs/12.19.0/firebase-app.js
  https://www.gstatic.com/firebasejs/12.19.0/firebase-auth.js
  https://www.gstatic.com/firebasejs/12.19.0/firebase-firestore.js
- 설정값은 아래를 그대로 써:
(여기에 firebaseConfig를 붙여넣으세요)
- Firestore의 classPortal 컬렉션 안 main 문서 하나에 안내판 내용 전체(학급 이름, 급훈, 시간표,
  알림, 일정과 그 밖에 저장하는 값)를 저장해.

[로그인과 저장]
- 머리말에 "구글 로그인" 단추(GoogleAuthProvider, signInWithPopup). 로그인하면 단추가 "로그아웃"으로 바뀌게.
- 선생님 계정(선생님이메일@gmail.com)으로 로그인했을 때만 저장(쓰기)해.
  보안 규칙도 이 이메일만 쓸 수 있게 되어 있어.
- 로그인하지 않은 기기는 읽기만: onSnapshot으로 실시간으로 받아서 화면을 바꿔.
- 입력할 때마다 저장하지 말고, 입력이 0.8초 멈추면 한 번 저장.
- 내가 저장한 것이 다시 돌아와서 화면을 덮어쓰지 않게 하고, 내가 글자를 입력하는 중에는
  다른 기기에서 온 변경으로 화면을 갈아엎지 말고 입력이 끝난 뒤에 반영해.
- 처음 연결했을 때 서버에 문서가 없고 선생님이 로그인했다면, 지금 이 기기의 내용을 올려.

[안전장치]
- 파이어베이스를 불러오지 못하거나 인터넷이 끊기면 지금처럼 localStorage로만 동작하고,
  오류 때문에 화면이 멈추지 않게.
- 머리말에 연결 상태를 작게 표시: "🟢 공유 중" / "🔵 로그인하면 저장돼요" / "⚪ 이 기기에만 저장".
- 오류가 나면 alert 대신 화면 안 글상자에 오류 코드(예: auth/unauthorized-domain,
  permission-denied)를 함께 보여 줘.
- 화면 아래 안내 문구를 "이 화면의 내용은 우리 반 모두에게 공유됩니다. 학생 이름 대신 번호를 쓰세요."로 바꿔.

8 올리고 내 주소에서 확인하기

  1. 받은 코드를 2단계처럼 index.html로 저장 → 4단계 5번처럼 깃허브에 다시 올립니다.
  2. 1~2분 뒤 내 주소를 열고 구글 로그인 → 선생님 계정 선택.
  3. 편집 모드에서 알림을 하나 추가합니다. 상태 표시가 공유 중인지 확인.
  4. 휴대폰이나 다른 컴퓨터에서 학생용 주소를 열어 방금 쓴 알림이 보이면 성공입니다.
  5. 파이어베이스 Firestore › 데이터 탭에서 classPortal › main에 내용이 생긴 것도 볼 수 있습니다.
로그인은 AI 미리보기나 내 컴퓨터 파일(더블클릭)에서는 되지 않습니다. 코드가 틀린 것이 아니라 허락된 주소가 아니기 때문입니다. 반드시 깃허브에 올린 내 주소에서 확인하세요.
5단계 끝 — 선생님이 로그인해서 고친 내용이 다른 기기의 학생용 주소에도 바로 보인다.

안 될 때

AI 미리보기가 안 보이고 코드만 길게 나옵니다 1단계

이유
제미나이에서 Canvas를 켜지 않았거나, AI가 미리보기를 만들지 않았습니다.
해결
제미나이는 Canvas를 켜고 다시 보내세요. 어느 도구든 "지금 만든 것을 미리보기로 보여 줘"라고 하면 됩니다. 2단계처럼 파일로 저장해 크롬에서 열어 봐도 됩니다.

화면이 하얗게만 나옵니다

이유
코드 어딘가의 오류로 멈춘 것입니다. 코드가 중간에 잘렸을 때도 그렇습니다.
해결
AI에게 "화면이 하얗게만 나와. 오류를 찾아서 고쳐 줘". 파일로 연 경우에는 크롬에서 F12 → Console 탭의 빨간 글자를 복사해 AI에게 함께 보내면 더 빨리 고칩니다.

고쳤더니 다른 기능이 사라졌습니다

이유
AI가 코드를 "기존 코드 그대로" 같은 말로 생략했고, 그대로 저장했습니다.
해결
번호 붙여 둔 이전 파일(index_2.html 등)로 돌아가세요. 그리고 이어 가기 첫 문장을 써서 "생략하지 말고 전체 파일로" 다시 부탁하세요.

index.html을 더블클릭했더니 메모장이 열립니다 2단계

이유
파일 이름이 실제로는 index.html.txt입니다.
해결
파일 확장명 보이기를 켜고 이름 끝의 .txt를 지우세요. 메모장에서 저장할 때 파일 형식: 모든 파일을 고르면 이렇게 되지 않습니다.

한글이 이상한 글자로 깨집니다 2단계

이유
메모장에서 저장할 때 인코딩이 UTF-8이 아니었습니다.
해결
메모장으로 다시 열고 파일 › 다른 이름으로 저장에서 인코딩: UTF-8로 저장하세요. 그래도 깨지면 AI에게 "코드 맨 위에 <meta charset="UTF-8">을 넣어 줘".

내 주소가 404(페이지 없음)로 나옵니다 4단계

해결
① 올린 직후라면 1~2분 기다렸다가 새로고침.
② Settings › Pages에서 Branch가 main으로 Save 되어 있는지 확인.
③ 파일 이름이 정확히 index.html인지(대문자·띄어쓰기 없이) 확인.
④ 저장소 첫 화면에 index.html이 바로 보이는지 확인 — 폴더 안에 들어가 있으면 주소가 달라집니다.
⑤ 저장소가 Public인지 확인.

주소는 열리는데 README 글자만 보입니다 4단계

해결
아직 index.html이 올라가지 않았거나 이름이 다릅니다. 저장소 파일 목록을 확인하세요.

고쳐서 올렸는데 예전 화면이 나옵니다 4단계

해결
1~2분 기다린 뒤 Ctrl + F5(강력 새로고침). 휴대폰은 브라우저를 완전히 닫았다가 다시 엽니다.

다른 컴퓨터에서 열었더니 적어 둔 내용이 없습니다

이유
고장이 아닙니다. localStorage는 기기마다, 주소마다 따로 있는 수첩입니다.
해결
그 기기에서 다시 적거나, 5단계로 파이어베이스를 연결하세요.

로그인 단추를 눌러도 창이 안 뜨거나 바로 닫힙니다 5단계

해결
auth/unauthorized-domain — 5단계 ⑥ 승인된 도메인에 아이디.github.io를 넣었는지, 철자가 맞는지 확인.
auth/popup-blocked — 크롬 주소창 오른쪽의 팝업 차단 표시를 눌러 항상 허용.
auth/operation-not-allowed — 5단계 ② Google 로그인을 사용 설정하고 저장했는지 확인.
AI 미리보기나 내 컴퓨터 파일에서 누른 경우 — 정상입니다. 깃허브의 내 주소에서 하세요.

로그인은 되는데 저장이 안 됩니다 (permission-denied) 5단계

해결
① 5단계 ④ 규칙을 붙여넣고 게시까지 눌렀는지.
② 규칙 속 이메일이 로그인한 계정과 한 글자도 다르지 않은지.
③ AI가 만든 코드가 classPortal 컬렉션에 저장하는지 — 이름이 다르면 AI에게 "classPortal 컬렉션의 main 문서에 저장하게 고쳐 줘".

학생 화면에서 바로 바뀌지 않습니다 5단계

해결
학생 기기에서 한 번 새로고침해 보세요. 그래도 안 되면 상태 표시를 확인합니다. 이 기기에만 저장이라고 나오면 그 기기가 파이어베이스에 연결되지 못한 것입니다(학교망 차단 등). 다른 인터넷(휴대폰 데이터)으로 열어 비교해 보세요.

그래도 모르겠다면

해결
AI에게 지금 상황을 그대로 말하세요. "깃허브에 올린 주소에서 로그인 단추를 누르면 auth/unauthorized-domain 이라고 나와. 무엇을 확인해야 해?" — 화면에 보이는 오류 글자를 그대로 복사해 주는 것이 가장 빠릅니다.

개인정보와 안전

지킬 것왜
학생 이름 대신 번호안내판·뽑기 결과는 교실 화면과 인터넷 주소로 보입니다. "3번 준비물 확인", "12번 보건실"처럼 씁니다.
AI에게 개인정보를 적지 않기학생 이름·연락처·주소, 상담 내용은 프롬프트에 넣지 않습니다.
저장소는 코드까지 공개깃허브 Public 저장소는 누구나 파일 내용을 볼 수 있습니다. 파일 안에 실명·연락처가 없는지 올리기 전에 확인합니다.
firebaseConfig는 공개 가능, 비밀 키는 절대 금지firebaseConfig는 웹페이지에 들어가는 공개용 값입니다. 서비스 계정 키, 비밀번호, 인증 토큰은 파일·AI 대화 어디에도 넣지 않습니다.
보안 규칙 게시 확인테스트 모드로 만들고 규칙을 안 넣으면 누구나 고칠 수 있는 상태가 됩니다. 이 가이드처럼 프로덕션 모드 + 선생님 이메일 규칙을 씁니다.
AI가 만든 것도 내 책임AI는 그럴듯하게 틀립니다. 올리기 전에 직접 눌러 확인하고, 학급 공지로 쓰기 전 내용을 한 번 더 봅니다.
